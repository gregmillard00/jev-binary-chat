Talking to a model that cannot talk

Jev does not generate text. It only returns typed judgments: a choice from a fixed set, a yes/no probability, a score. So this page makes it write anyway. Every word of every reply is chosen by a tournament over a {{ "{:,}".format(vocab) }}-word dictionary: {{ groups }} groups of {{ group_size }} compete in one request, then the {{ groups }} group winners compete in a second. Two requests per word. Nothing is generated, only chosen.

Why a tournament, and not the binary search this started as

Binary search over an alphabetical dictionary cannot work. Measured, not assumed: across a full 13-step search the model's answers sat between 0.39 and 0.48 at every single step. Thirteen coin flips, and the output was accepting. The alphabet carries no meaning, so is the next word before or after melon has no signal in it. Both halves contain every kind of word. Sorting by word frequency roughly doubles the signal and still returns nonsense, because rank 4000 and rank 4001 have nothing to do with each other either.

Character by character fails harder. Asked for the next letter of The capital of France is Par, Jev answers a. For Two plus two equals fou, e. That is not a prompting problem. Continuing a string of characters is exactly the generative task a judgment model does not do.

What it is excellent at is choosing between candidate words on meaning. Asked which word best begins a reply to thanks for your help, it picks welcome at 0.94 and puts banana at 0.00. So every question here is a semantic one, and the dictionary is searched by elimination rather than by bisection.

The one real constraint is the token budget. All {{ groups }} group questions ride in a single request because System One evaluates questions in parallel and extra questions are nearly free. Around 5,000 options is the ceiling; 10,000 returns max_tokens_exceeded. That is why the vocabulary is the 5,000 most common English words.
